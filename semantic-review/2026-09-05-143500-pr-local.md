# Financial capture hardening and cycle-accounting corrections

This diff routes bulk settlement through the shared service, makes default scheduling use UTC hour boundaries, and separates fought 1v1 battles from byes in cycle totals. Bye rewards now carry a durable financial identity and are paid only after the queued-row claim succeeds. The forward-only rollout remains intact: legacy cycles retain compatibility behavior, while post-cutover mutations require the paired ledger and audit records. The complete-cycle test creates its own eligible tag-team cohort instead of silently skipping assertions. Watch for: no blocking concerns found in the reviewed changes.

**Verdict**: APPROVED

## High-level view

Pre-cutover calls preserve legacy balance and optional legacy-ledger behavior without asserting completeness; post-cutover calls enter the transactional paired-capture path and fail when the durable rollout state cannot support it.

Bulk administration no longer has a second settlement writer. It delegates to `Settlement_Service`, preserving separate component identities and the zero-value component policy.

The bye path claims the scheduling token before payment and carries a deterministic battle-income identity into the shared credit writer. The 1v1 summary now counts a completed bye only as a bye, never as simulated combat.

All matchmaking services retain their optional `scheduledFor` parameter and use the shared UTC-hour default only when callers omit it. Removing local-time construction from the admin cycle path does not change explicit overrides.

The implementation record leaves ACC activation pending while backend lint/build/test typecheck, frontend lint, and E2E results remain incomplete.

## Forward-only financial capture

`Credit_Mutation_Service` enters `assertPairedCaptureForCycle` at and after the immutable cutover. The balance update, financial ledger insert, and `financial_transaction` audit insert are transactional there; optional legacy enrichment cannot suppress this path. The implementation record matches the code by withholding the cutover gate until its incomplete verification results are resolved.

## Claim-before-payment bye resolution

`resolveByeEvent` wins the scheduled-match or tournament claim before calling `awardCreditsWithLedger` with the bye source identity and typed battle-income facts. A post-claim failure leaves the documented, detectable unpaid signature rather than allowing a retry to duplicate credits. `executeScheduledBattles` increments `byeBattles` for that path and increments `successfulBattles` only for fought battles.

## Shared UTC default and settlement delegation

`defaultScheduledFor` rounds the 24-hour lead time with UTC setters, while all matching services continue to use `scheduledFor ?? defaultScheduledFor()`. `AdminCycleService` therefore uses the shared default without discarding caller-provided scheduling values, and its daily-finance block delegates to `Settlement_Service` rather than applying a net balance delta.

## Self-contained fought tag-team assertion

The complete-cycle test builds two subscribed, standing-backed teams, schedules and executes them, then fails if no battle exists. This removes the prior cross-test dependency and early return that could leave the battle-log assertion unexecuted.
