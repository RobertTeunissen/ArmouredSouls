## Direct-writer coverage no longer fails closed for all alias mutations

**Confirmed.** `collectVariableBindings` in `app/backend/src/services/migration/directWriterCoverage.ts` marks a binding dynamic only for a `PropertyAccessExpression` whose left side is an identifier and whose final property is `currency`. Consequently, this production write is reported as no mutation:

```ts
const args = { data: {} };
args.data['currency'] = { increment: 10 };
tx.user.update(args);
```

The computed access is not a `PropertyAccessExpression`; even `args.data.currency = …` is missed because its immediate left expression is itself a property access rather than an identifier. The resolver then follows the original `{ data: {} }`, returns `null`, and `checkDirectWriterCoverage()` does not list an uncovered writer. A new direct current-economy assignment can therefore bypass the writer-manifest gate after cutover.

Track writes through nested object paths and `ElementAccessExpression` with a literal `"currency"` key, or conservatively mark the owning alias unresolved/dynamic whenever an assigned path can reach a `data.currency` field. Add fixtures for both forms and retain the existing non-currency assignment case so the false-positive correction remains protected.
