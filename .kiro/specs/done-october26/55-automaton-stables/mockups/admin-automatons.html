Spec 55 — Automaton Stables: admin page mockups

Static mockups of /admin/automatons inside the existing admin layout. Desktop (≥ 1024 px) shows tabs; from 320 to 1023 px the four sections stack vertically below the status bar (the TabLayout pattern), as in the mobile frames. All touch targets are at least 44 px.

Sample data comes from the starter catalogue. Numbers are illustrative.

1 · Status bar and Stables tab

The status bar sits above the tabs and is the same on every tab: the on/off switch, when the Automatons last acted, whether any stable failed, and how many need attention. "Needs attention" opens the Stables tab with that filter on. The Stables tab lists every Automaton with its progress; click a row to open it in the Editor.

2b · Strategies tab: Strategy library and Strategy builder

Added after approval (README decision 20). The Strategies tab has two views: Comparison (above) and Library. The library lists every strategy and version in the repository and how many stables use each version. "New strategy" and "New version" open the builder. A draft can be previewed and exported, but never used by a stable: the exported file reaches stables only through a pull request whose CI runs the shared strategy tests. Stables stay on their version until you upgrade them. Swarm v2 and the two drafts are illustrative: they show the state after a future pull request. The builder frame shows a draft with three rule errors, so Export is disabled. Changed after approval (decisions 29–30): the Paragon build order has 24 goals; the builder shows the rule that every goal type is needed at least once, with a Build_Order-level error above the goal list (here: the draft has no Tuning Bay goal). Changed after approval (decisions 35–36): Refine targets count plan steps per robot, allowed 0–10 (Paragon goal 16: 10 steps; the Swarm draft's goal 23: 8 steps).

3 · Editor tab

One stable at a time. Left: the stable card (identity, backstory and the stable's event order), the numbered build order with editable targets and a status per goal, the team names and robot blueprints (one expanded). Right: what the stable would do next cycle, and its cycle history. The build order comes from the strategy; only the targets can be changed. A 🔒 marks a goal that is (or will be, when reached) blocked by a prestige gate. Both Swarm stables use the default goal 10 (Robots → 11): robots behind a prestige gate are Blocked and cost nothing. Changed after approval (decisions 21–26): Backstory replaces Bio, the event order moved from the blueprint to the stable, Teams shows the fixed team rule with team names, the extra-robot fields are gone, and weapon paths go starter → final. Changed after approval (decisions 29–30): the Swarm build order has 25 goals with every goal type, and Rex has a refinement plan. Changed after approval (decisions 35–36): goal 23 is "Refine → 8 steps" (allowed 0–10), and Rex's plan covers both Volt Sabres, Sharpen and Forge first, interleaved by hand, with the two Hones last. Changed after approval (consistency fix): the Editor header gains New stable and Delete draft stable (enabled for drafts only, disabled for an active stable as here); blueprints gain Delete blueprint, disabled while a robot built from it is in play.
