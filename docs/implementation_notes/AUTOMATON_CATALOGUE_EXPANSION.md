## Integration tier (local dev DB)

`pnpm run test:integration` against `armouredsouls` after Group 4: exit 1, 135 of 142 suites passed, 59 of 1717 tests failed in seven suites. CI runs this tier on a fresh database without a Catalogue_Sync, so the CI result is unaffected. All seven suites pass (76 tests) when rerun unchanged against the local `armouredsouls_heavy`, which holds no Automaton_Profile, so they fail on local dev data, not on code:

- `userGeneration`, `metricProgression.property`, `eloProgression.property`, `leagueRebalancingService`, `battleEventLogging`: broad `user.deleteMany` blocked by `automaton_profiles_user_id_fkey`. The users belong to the 11 active starter profiles, which were on the dev DB before this delivery; drafts have no user.
- `automatonPublicExposure` (Hall of Records narrowest victory has no `stableType`): local dev battle data; passes on the clean database.
- `automatonNeedAttention` (`filters the list on Need_Attention`): most likely caused by the 194 local drafts. The test lists `?limit=100` ordered by Catalogue_Key, so with 205+ profiles its healthy test stables fall beyond the first page. This test fragility appears only on a database that holds the synced catalogue. It is reported, not changed.

The local drafts were left in place (reversible; delete them through the admin page or the database if a clean dev DB is wanted).
